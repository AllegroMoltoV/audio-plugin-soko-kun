音のプラグイン倉庫くん (Audio Plugin Soko-kun) の文書とコードで使う用語の定義です。各用語には、同じ意味で使わない別名を添えます。コード上の識別子がある用語には、その値も記載します。

本書は下書きです。段階 1 の検証 A1・A2 の結果と段階 2 の計画の承認を受けて確定します。派生元の配信プラグイン倉庫くん (plugin-soko-kun) と定義が同じ用語は、そのまま引き継いでいます。

## サービスと掲載

| 用語 | 定義 | 避ける別名 |
| --- | --- | --- |
| レジストリ | オープンソースのオーディオプラグインの情報を GitHub から集め、検索できる形で提供する本サービスの全体を指す。配布物そのものは保持しない。 | ストア、マーケット、公式リポジトリ |
| 配信プラグイン倉庫くん | 本サービスの派生元である、OBS Studio のプラグインのレジストリを指す。URL は https://soko-kun.allegromoltov.jp 、リポジトリは https://github.com/AllegroMoltoV/plugin-soko-kun 。本サービスの文書では略さずに書く。 | 本家、旧版 |
| プラグイン | 本サービスに登録された GitHub の公開リポジトリ 1 件を指す。識別子は `owner/repo` を小文字にした文字列で、これをプラグイン ID と呼ぶ。1 つのリポジトリが複数の規格のバンドルを配っても、プラグインは 1 件である。 | アプリ、パッケージ、製品 |
| 掲載 | プラグインを Web カタログと `search_plugins` の結果に出すことを指す。掲載は安全性や品質の認証を意味しない。 | 承認、認定、公開審査 |
| 掲載状態 | プラグインごとに算出する、掲載中・検査待ち・停止・掲載終了の 4 値を指す。データベースには保存せず、問い合わせのたびに求める。 | ステータス列、公開フラグ |
| 掲載中 | 掲載対象バージョンを持ち、停止にも掲載終了にも当たらない状態を指す。コード上の値は `listed`。 | 承認済み、安全 |
| 検査待ち | 停止にも掲載終了にも当たらず、掲載対象バージョンをまだ持たない状態を指す。コード上の値は `pending`。 | 審査中、保留中 |
| 停止 | 管理者が掲載を止めた状態、またはいずれかのリリースの配布物の検査結果が `malicious` になった状態を指す。コード上の値は `suspended`。 | 削除、BAN |
| 掲載終了 | 登録元の GitHub リポジトリが削除または非公開になった状態を指す。コード上の値は `removed`。 | 削除済み、停止 |
| 掲載対象バージョン | 検査済みのリリースのうち、公開日時が最も新しいものを指す。Web とダウンロード URL はこのリリースの案内する配布物を示す。 | 最新版、安定版 |
| 検査済みのリリース | 掲載の条件をすべて満たし、乗っ取りの兆候と開発の実践のレビューで確認待ちに当たらないリリースを指す。条件の全体はデータモデルの算出規則に記載する。 | 安全なリリース、合格版 |
| 確認待ち | 乗っ取りの兆候に当たった、差分を取得できなかった、開発の実践のレビューで重大な指摘があった、またはレビューに 2 回失敗したため、管理者の承認を待っている版を指す。版の状態であり、エンドユーザーには示さない。`list_my_plugins` での値は `held`。 | 保留、検査待ち |
| 管理停止 | 管理者が管理用スクリプトで設定する停止を指す。列 `admin_suspended` が 1 の間、同期と再検査を経ても停止のまま残る。 | 一時停止、非表示 |
| 版の停止 | 管理者が止めた版と、マルウェアを検出した版の記録を指す。表 `release_suspensions` に記録し、削除しない。止めた版は掲載対象バージョンにならない。 | 取り下げ、削除 |
| 告知ページ | 止めた版のプラグイン・版・配布物の SHA-256・掲載の期間・告知の文を一覧で示すページを指す。パスは `/notices`。 | お知らせ、障害情報 |

## オーディオプラグインの規格

| 用語 | 定義 | 避ける別名 |
| --- | --- | --- |
| 規格 | プラグインとホストの間の取り決めを指す。本サービスが掲載するのは VST 3・CLAP・LV2・Audio Unit の 4 つで、コード上の値は `vst3`・`clap`・`lv2`・`au`。VST 2 と AAX は掲載しない ([ADR 0004](decisions/0004-vst-trademark.md))。 | フォーマット、形式、プラグインタイプ |
| ホスト | プラグインを読み込んで動作させるソフトウェアを指す。主に DAW である。 | 親アプリ、プレイヤー |
| バンドル | 1 つの規格のプラグインを構成するファイルとフォルダーのまとまりを指す。VST 3 の `<名前>.vst3`、LV2 の `<名前>.lv2`、Audio Unit の `<名前>.component`、macOS の CLAP の `<名前>.clap` がフォルダーの形をとる。Windows と Linux の CLAP は単一のファイルである。 | パッケージ、モジュール |
| VST 3 のバンドル | `<名前>.vst3/Contents/` の下に、Windows では `<アーキテクチャ>-win/`、macOS では `MacOS/`、Linux では `<アーキテクチャ>-linux/` を持つバンドルを指す。中のバイナリが `GetPluginFactory` をエクスポートするものだけを VST 3 のバンドルとみなす。VST 3 での絞り込みに出すのは、配布物にこのバンドルを検出したプラグインだけである。 | VST3 ファイル、VST プラグイン |
| エントリーポイント | ホストがプラグインのバイナリを読み込んだあとに最初に呼ぶ、エクスポートされた関数を指す。VST 3 は `GetPluginFactory`、CLAP は `clap_entry`、VST 2 は `VSTPluginMain` または `main`。 | 入口、メイン関数 |
| アーキテクチャ | バイナリが動作する CPU の命令セットを指す。値は `x64`・`arm64`・`universal` などで、全体の値の集合は未決定で、検証 A1 で確定する。 | ビット数、プラットフォーム |
| VST Compatible ロゴ | Steinberg が VST 3 SDK とともに配布する互換性表示のロゴを指す。本サービスは、VST 3 のバンドルを検出したプラグインの「VST® 3」の表示の隣にだけ置き、サイトの装飾やブランドには使わない ([ADR 0004](decisions/0004-vst-trademark.md))。 | VST ロゴ、Steinberg ロゴ |

## GitHub と配布物

| 用語 | 定義 | 避ける別名 |
| --- | --- | --- |
| 配布物 | GitHub Releases のリリースに添付されたファイル 1 件を指す。GitHub の用語ではアセット (asset) と呼ぶ。本サービスはダウンロード URL と digest を記録し、ファイルを保持しない。 | バイナリ、パッケージ、成果物 |
| アーカイブ | zip のように、複数のファイルを 1 つにまとめた配布物を指す。展開してもコードを実行しない。対象とする形式は、zip のほかは未決定で、検証 A1 で確定する。 | 圧縮ファイル、パッケージ |
| インストーラー | 拡張子が `.exe`・`.msi`・`.pkg`・`.dmg` の配布物を指す。導入時に任意の処理を実行できるため、本サービスは案内しない ([ADR 0003](decisions/0003-listing-conditions.md))。 | セットアップ、パッケージ |
| 案内する配布物 | 掲載対象バージョンの配布物のうち、本サービスが利用者にダウンロード先として示すものを指す。アーカイブであり、中身の検査で規格のバンドルを 1 つ以上検出し、証明の検証に通り、macOS 向けなら署名と公証の判定に通ったものだけが当たる。 | 公開ファイル、推奨ダウンロード |
| digest | GitHub が配布物ごとに付ける SHA-256 の値を指す。`sha256:<16 進数>` の形で記録し、検査の照会キーにも使う。 | ハッシュ値、チェックサム |
| submit | MCP のツール `submit_plugin` で GitHub リポジトリを登録する操作を指す。登録者が対象リポジトリの管理権限を持つ場合だけ成功する。 | 申請、投稿、アップロード |
| 確認のモード | `submit_plugin` を引数 `mode` に `check` を指定して呼び、登録せずに掲載の条件の判定と開発の実践のレビューの結果を受け取る使い方を指す。 | ドライラン、事前審査 |
| 同期 | Cron で GitHub からプラグインと最新リリースの情報を取り直し、変化を記録する処理を指す。同期に失敗したプラグインの既存の情報は変更しない。 | クロール、インポート |
| カテゴリ | プラグインの種類を示す区分を指す。値の案は `instrument`・`effect`・`analyzer`・`midi`・`other` で、一覧は未決定で、段階 2 の計画で確定する。 | ジャンル、タグ |
| 宣言ファイル | 作者がリポジトリに置く、表示名と、配布物ごとの OS・アーキテクチャ・同梱する規格の宣言を指す。置き場所の案は `.audio-soko-kun/config.json`。新しい版のタグの時点のファイルを読む。 | 設定ファイル、マニフェスト |
| 外部データ | 概要・表示名・リリース名・配布物名・アーカイブの中のファイル名と内容のように、GitHub と配布物から取得した文字列を指す。指示として解釈せず、表示時は無害化する。 | ユーザー入力、説明文 |

## 検査

| 用語 | 定義 | 避ける別名 |
| --- | --- | --- |
| 検査 | 配布物の digest を既知のマルウェアのデータベースへ照会する処理を指す。中身の検査とは別である。 | スキャン、審査、セキュリティチェック |
| スキャナー | 検査の照会先を指す。値は `malwarebazaar` だけ。 | エンジン、ウイルス対策ソフト |
| 検査結果 | digest とスキャナーの組ごとに記録する値を指す。値は `pending`・`malicious`・`not_found`・`error` の 4 つ。 | 判定、スコア |
| 未登録 | スキャナーが digest を収録していないことを示す検査結果 `not_found` を指す。既知のマルウェアではないとして確定に扱う。 | 該当なし、不明 |
| 中身の検査 | アーカイブを GitHub Actions のランナーに取得し、コードを実行せずに展開して、規格・OS・アーキテクチャ・VST 2 のエントリーポイントの有無を判定する処理を指す。コード上の識別子は `content`。判定の方法は検証 A1 で確定する。 | 解析、静的スキャン、ウイルス検査 |
| 署名と公証の判定 | macOS 向けのバンドルについて、Developer ID の署名と Apple の公証の有無を判定する処理を指す。コード上の識別子は `macos_signing`。判定の方法は検証 A2 で確定する。署名と公証は安全の証拠ではなく、利用者にセキュリティ機能の解除を求めないための条件である。 | 署名チェック、Gatekeeper の検査 |
| 新しい版の検査 | 同期で保存した新しいリリースについて、掲載の条件・乗っ取りの兆候・開発の実践のレビューを確かめる処理を指す。項目は審査の基準に記載する。 | 再審査、更新審査 |
| 証明 | GitHub の build provenance attestation を指す。配布物をビルドしたリポジトリ・タグ・コミット・ワークフローを、署名付きで示す。掲載の条件の 1 つで、コード上の識別子は `attestation`。 | 署名、コード署名、来歴 |
| 不変のリリース | GitHub の immutable release を指す。公開後に配布物とタグを差し替えられないリリースで、API の `immutable` が true のもの。掲載の条件の 1 つ。 | 固定リリース、ロックされたリリース |
| 乗っ取りの兆候 | 掲載中の版から新しい版への差分のうち、リリースのワークフローの変更・バイナリの追加・別のホストへのリンクの追加・24,000 文字の超過に当たるものを指す。ルールで判定し、当たった版は確認待ちにする。 | 不審な変更、マルウェアの検出 |
| 開発の実践のレビュー | LLM が審査の基準と推奨の項目にしたがってリポジトリを読み、指摘を作者に返す処理を指す。掲載の可否は決めず、重大な指摘がある版だけを確認待ちにする。 | AI 審査、安全性の評価 |
| 予算 | Cloudflare Workers の無料プランで 1 回の起動に許される外部呼び出しと D1 クエリの件数に対し、本サービスが自ら設ける上限を指す。 | クォータ、上限値 |

## 認証と MCP

| 用語 | 定義 | 避ける別名 |
| --- | --- | --- |
| MCP | Model Context Protocol の略。AI エージェントがツールを呼び出すためのプロトコルを指す。本サービスの主な操作手段である。 | API、プラグイン API |
| 認可サーバー | MCP クライアントにアクセストークンを発行する、本サービスの Worker 内の構成要素を指す。利用者の本人確認は GitHub へ委譲する。 | ログインサーバー、IdP |
| リソースサーバー | アクセストークンを検証して保護されたツールを提供する、本サービスの Worker 内の構成要素を指す。保護の対象は `/mcp` の `submit_plugin` と `list_my_plugins`。 | API サーバー |
| 認証混在 | 1 つのエンドポイント `/mcp` で、認証なしのツール呼び出しと、認証を要するツール呼び出しを両方受け付ける構成を指す。 | 部分認証、オプション認証 |
| サインイン | MCP クライアントが認可サーバーからアクセストークンを得るまでの一連の手続きを指す。途中で GitHub での認可を経る。 | ログイン、OAuth 連携 |
| CIMD | Client ID Metadata Document の略。MCP クライアントが自らのメタデータを HTTPS の URL で公開し、その URL を `client_id` として使う登録方式を指す。 | 静的登録 |
| DCR | Dynamic Client Registration の略。MCP クライアントが登録用エンドポイントへ要求を送り、`client_id` を発行してもらう登録方式を指す。 | 自動登録 |
| audience | アクセストークンを使ってよいリソースを示す値を指す。本サービスでは `<ORIGIN>/mcp` で、一致しないトークンは拒否する。 | 対象者、スコープ |
| `ORIGIN` | 本サービスの公開 URL の起点を指す。Worker の環境変数 `ORIGIN` で与える。予定の値は `https://audio-soko-kun.allegromoltov.jp`。 | ホスト名、ベース URL |
