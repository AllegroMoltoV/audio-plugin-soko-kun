# ADR 0003: 掲載の条件を倉庫くんと同じ強さに保ち、macOS には署名と公証を求める

- 状態: 採用 (2026-11-14)

## 背景

2026-02 に、OBS Forums で作者のアカウントが乗っ取られ、掲載中のプラグインの配布物が悪意のある版に差し替えられる事件が起きました。OBS Forums の管理者は 2026-03-09 にこの事件を公表しました (https://obsproject.com/forum/threads/resource-security-incident.194555/)。倉庫くんは、この事件を受けて、不変のリリースと全配布物の build provenance の証明を掲載の条件にしました。

オーディオプラグインでも、クラック版のプラグインを装ったマルウェアが繰り返し確認されています。2019 年の LoudMiner、2020 年の ThiefQuest、2026 年の音楽プラグインの DMG を装うローダーが例です。オーディオプラグインは DAW のプロセスの中で動作し、未発表の楽曲やプロジェクトのファイルに触れます。

一方で、GitHub の上位のオーディオプラグイン 197 件のうち、最新のリリースの配布物に証明があったのは 6 件でした。インストーラーでの配布も一般的です。macOS では、署名の無いプラグインに対して、Gatekeeper の隔離属性を外す手順を README で案内する例が多く見られます (非公開の調査記録)。

## 決定

掲載の条件を次のとおりにします。

1. リリースが不変 (immutable release) である
2. リリースのすべての配布物に、そのリポジトリ・タグ・コミットに一致する build provenance の証明がある。案内しないインストーラーも含む
3. 案内する配布物は、zip のアーカイブに限る。exe・msi・pkg・dmg のインストーラーは案内しない
4. macOS 向けの配布物は、Developer ID の署名と Apple の公証があるものだけを案内する

Windows の署名は条件にしません。

入手は常に GitHub の公開リリースから無料です。有料の配布は次の 3 つの型で扱います (2026-11-19 依頼者の決定、配信プラグイン倉庫くんと共通)。

| 型 | 内容 | 扱い |
| --- | --- | --- |
| A | 同じファイルを GitHub で無料公開し、外部でも販売や寄付を受ける | 掲載できる |
| B | 一部の機能を有料で解放する | 宣言ファイルの `paidFeatures` で申告すれば掲載できる |
| C | ソースを公開しない有料のファイルだけを配る | 対象外 |

型 C を対象外とする理由は、購入の前に中身を検査できないためです。有料の機能・外部の有料サービス・同梱素材の利用の制限・支援と購入のページは、作者が宣言ファイルで申告し、画面と MCP に表示します。本サービスは申告を確かめません。申告の誤りでは掲載を止めず、導線と審査は変えません。コードのライセンスは、条件の OSI か FSF の判定で確かめた事実として、申告とは分けて表示します。

条件を満たさない版の理由と直し方は、作者の LLM に MCP で返します。条件を厳しくする負担を、作者のエージェントが担える形にするためです。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 倉庫くんと同じ強さを保ち、macOS には署名と公証を求める | 採用しました。セキュリティ機能の解除を利用者に求めずに済みます |
| 証明を必須にせず、加点として表示で区別する | 採用しませんでした。立ち上げ時の掲載数は増えますが、乗っ取りによる差し替えを止められない版が載ります |
| インストーラーを認め、中身を展開して検査する | 採用しませんでした。インストーラーは導入時に管理者権限で任意の処理を実行できます。中身の展開と preinstall・postinstall のスクリプトの検査を確実に行う手段がありません |

## 影響

立ち上げ時の掲載は少なくなります。

macOS 向けのプラグインの多くは載りません。署名と公証の判定の方法は、[検査と同期](../design/scanning.md) に記載します。

署名と公証は、安全の証拠ではありません。Apple の公証は提出時の検査で、公証を通ったマルウェアの例が 2025 年に複数報告されています (非公開の調査記録)。macOS の条件は、利用者にセキュリティ機能の解除を求めないためのものです。

インストーラーとアーカイブを並べて出すリリースでは、アーカイブだけを案内します。インストーラーにも証明を求めるのは、乗っ取ったアカウントで手作業でビルドしたインストーラーが同じ版に紛れることを、証明の欠けで検出するためです。利用者が GitHub のリリースのページからインストーラーを直接取得することは止められません。
