## 背景

[ADR 0002](0002-independent-service-derived-from-soko-kun.md) では、配信プラグイン倉庫くん (以下、倉庫くん) のコードを写し、以後は独立に保守すると決めました。ADR 0002 の影響の節に書いたとおり、共通の不具合やセキュリティの修正は、両方のリポジトリに行う必要があります。

2026-11-15 までの運営で、同じ不具合を両方で直す場面が続きました。定期処理で検査が飛ばされる不具合、README の照合を逃れられる欠陥、AI Gateway の指定がその例です。共通の部分の形がずれていると、片方の修正を写すたびに直し方を考え直すことになり、脆弱性が残る時間が延びます。

## 決定

両方のサービスに共通の土台だけを、同じ内容に保ちます。土台を直すときは倉庫くんを先に直し、本サービスはその変更を写します。土台に触る変更をしたときは、相手のサービスの運営に知らせます。

共通の土台は次の 5 つです。

| 土台 | 本サービスのファイル |
| --- | --- |
| 認証 | `src/auth/` |
| 外部呼び出しの予算 | `src/budget.ts` |
| AI Gateway の指定 | `src/ai-gateway.ts` |
| GitHub の呼び出し | `src/github.ts` |
| 証明の検証の受け口と OIDC | `src/checks/` |

「同じ内容」の範囲は次のとおりです。

- 両方にある関数と処理は、同じ実装に保つ
- サービス名の文字列と、片方だけに要る関数の追加は違ってよい
- 片方だけにあった関数を相手が取り込んだら、写す形で取り込み、以後は同じ実装に保つ
- 受け口は検査の種類が違うため、ファイルの全体ではなく次の 5 つの決まりをそろえる
  - OIDC のトークンの検証を通らない要求を 401 で拒否する
  - 検証待ちの条件を 1 か所に置き、受け口の一覧と定期処理のワークフローの起動で共有する
  - 同じ対象の結果を 2 つ含む要求を、全体で拒否する
  - 試行を使い切った対象を作者に管理者の待ちとして返し、管理コマンドで検証待ちに戻せる
  - 確定した行は、遅れて届いた結果で書き換えない

試行を使い切った行に遅れて届いた結果を受け入れるかは、各サービスに任せます。本サービスは受け入れます。土台の外 (掲載の条件、検査の種類、審査の基準、画面、文書) は、それぞれが自由に変え、良いものはその都度写します。土台の範囲を変えるときは、運営者が判断します。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 共通の土台だけを同じ内容に保ち、倉庫くんを先に直す | 採用しました。共通の脆弱性を、同じ直し方で両方に入れられます。土台の外は独立に変えられます |
| ADR 0002 のとおり、すべてを独立に保守する | 採用しませんでした。共通の部分の形がずれ、修正を写すたびに直し方を考え直すことになります |
| 共通の部分をパッケージとして切り出して共有する | 採用しませんでした。ADR 0002 で避けた、片方の事情による変更がもう片方に影響する問題が残ります。共有の仕組みの保守も増えます |

## 影響

土台の修正は、倉庫くんの変更を待ってから写します。本サービスで見つけた土台の不具合も、倉庫くんに知らせて先に直してもらいます。

土台の範囲と 5 つの決まりの現在の内容は、[アーキテクチャ](../design/architecture.md) に記載します。
