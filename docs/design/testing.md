音のプラグイン倉庫くんの自動テストで守るラインと、テストシナリオの仕様です。テストのコードは、本サービスのリポジトリに置きます。

中身の検査と、macOS の署名と公証の判定の期待値は、[検査と同期](scanning.md) の規則によります。

## 方針

テストは、将来の変更で壊されると危険側に倒れるラインにだけ書きます。危険側とは、権限の逸脱・掲載してはいけない版や配布物の掲載・情報の漏洩のように、壊れても利用者と作者が気づかないまま実害に至る帰結を指します。表示が減る、処理が遅れる、といった安全側の帰結で、テストが実装の写しになるものは書きません。ただし、派生元の配信プラグイン倉庫くんから写したテスト、それを本サービスの検査に合わせたテスト、本番で起きた不具合の再発を防ぐテストには、安全側の挙動を確かめるものも含まれます。これらは残し、[安全側の挙動](#安全側の挙動) の表に記載します。

権限のテストでは、権限の無い人が拒否されることを、守りたい境界の際から確かめます。期待するステータスコードは厳密に照合し、401 を期待する箇所で 403 や 404 が返ったら失敗にします。権限がある人のテストは、拒否のテストが空振りしていないことを示す対照として、境界ごとに 1 件だけ置きます。

テストの実行環境は、配信プラグイン倉庫くんと同じ構成にします。

| 項目 | 内容 |
| --- | --- |
| テストランナー | Vitest と `@cloudflare/vitest-plugin`。Workers のランタイムの上で、`SELF.fetch` で Worker へ要求を送る |
| 外部呼び出し | `@msw/cloudflare` でモックする。未定義の外部呼び出しをテストの失敗にし、モックの漏れで実ネットワークへ出ないようにする |
| D1 と KV | 各テストの前に消し、`migrations/` を当て直す |
| 秘密情報 | テスト用の値を `vitest.config.ts` の bindings で与える |
| 中身の検査と macOS の判定のスクリプト | Worker のテストとは別に、本サービスのリポジトリの CI で実行する。どちらのスクリプトも Python の標準ライブラリで書く。macOS の判定のテストは、`codesign` と `spctl` の出力を入力にするため、Linux のランナーで実行できる |

フィクスチャの利用者名とメールアドレスのローカル部には、運営者のハンドル `allegromoltov` を使います。管理者でない利用者は `allegromoltov-other` のように、運営者のハンドルに語を足して作ります。ドメインには `.example` を使い、連絡先のメールアドレスは `allegromoltov@audio-soko-kun.example` にします。フィクスチャのリポジトリ名は `audio-fixture-pitchshift` にします。

## 守るライン

| ID | ライン | 壊れたときの帰結 | 側 | テスト | 判断の理由 |
| --- | --- | --- | --- | --- | --- |
| L01 | 認証を要するツールは、トークンの無い要求と偽のトークンを拒否する | 誰でも他人として登録や作者向けの情報の取得ができる | 危険側 | 書く | 権限の逸脱の入口で、利用者からは異常が見えない |
| L02 | 認証なしの MCP ハンドラに、認証を要するツールを通さない | `Mcp-Name` ヘッダーと本文の食い違いで、リソースサーバーを迂回される | 危険側 | 書く | 振り分けの規則が複数の条件に分かれ、変更で崩れやすい |
| L03 | `submit_plugin` は、対象リポジトリの管理者でない利用者の要求で登録しない。確認のモードでも同じ | 他人のリポジトリを登録できる。確認のモードでは他人の要求で Workers AI の枠を消費される | 危険側 | 書く | 登録の可否を決める唯一の境界 |
| L04 | `list_my_plugins` は、現在の管理者にだけ版の状態・理由・レビューの指摘を返す | 掲載していない版の情報と、作者だけに返す指摘が漏れる | 危険側 | 書く | 候補の決め方と管理権限の確認の 2 段で守っており、片方が崩れても気づきにくい |
| L05 | `/internal/` 配下の経路は、本サービスのリポジトリの main で動作する、経路ごとに決めたワークフローの OIDC のトークンだけを受け付ける。`/internal/checks/` は `verify.yaml`、`/internal/macos-checks/` は `macos-verify.yaml` | 第三者が検証の結果を偽り、条件を満たさない配布物を掲載させる | 危険側 | 書く | OIDC のトークンは GitHub Actions を使う誰でも発行でき、`aud` も要求側が選べる |
| L06 | 受け口が受け取った結果で、掲載の条件をすり抜けさせない | 確定した失敗の上書き、署名したワークフローのすり替え、macOS の判定の省略で、掲載してはいけない配布物を案内する | 危険側 | 書く | 正しいトークンを持つワークフローの誤りも、そのまま掲載に反映される |
| L07 | 掲載状態の算出で、条件を満たさない版と配布物を案内しない | VST 2 を含む版、判定不能のアーカイブを含む版、インストーラー、公証の無い macOS の配布物、証明の無い配布物を含む版、オープンソースのライセンスの無い版を案内する | 危険側 | 書く | 条件の数が多く、組み合わせの変更で抜けが生じやすい |
| L08 | 検査待ち・停止・掲載終了のプラグインを、一覧・検索・サイトマップ・右の列に出さず、ダウンロード URL を返さない | 検査を通っていない配布物を案内する | 危険側 | 書く | 一覧ごとに別の問い合わせを書くと、1 つだけ条件が抜ける |
| L09 | 管理停止と版の停止と掲載の期間の記録を、同期と削除で失わない | 停止したプラグインが自動で掲載に戻る。侵害のときに影響を受けた版と期間を示せない | 危険側 | 書く | 同期と連鎖削除は停止と無関係に見える処理で、変更の影響に気づきにくい |
| L10 | 所有者の変更と、新しく現れた配布物を見逃さない | 乗っ取られたリポジトリの新しい版や、差し替えた配布物を、過去の検査結果で掲載する | 危険側 | 書く | 同じ `digest` の結果の流用は、効率化の変更で入りやすい |
| L11 | 外部データを Web で無害化し、MCP で指示と区別できるフィールドに入れる | XSS と、利用者の LLM へのプロンプトインジェクション | 危険側 | 書く | 外部データの入口が多く、新しい表示の追加で漏れる |
| L12 | LLM の出力とリポジトリの内容で、重大な指摘を消させず、本サービスの固定の文言を書き換えさせない | 重大な指摘のある版を自動で掲載する。作者に危険な直し方を返す | 危険側 | 書く | LLM の応答は攻撃者が書いたリポジトリの内容に左右される |
| L13 | 中身の検査で、絶対パス・`..`・シンボリックリンクの項目を読まず、判定できないものを `passed` にしない | ランナーの侵害、VST 2 を含む版の掲載 | 危険側 | 書く | 判定のスクリプトの誤りが、そのまま掲載に反映される |
| L14 | 署名と公証の判定で、陰性と照会の失敗を `passed` にしない | 利用者にセキュリティ機能の解除を求める配布物を案内する | 危険側 | 書く | `spctl` の出力の読み違いが、そのまま掲載に反映される。照会の失敗と却下は出力で区別できないため、Developer ID の署名があり公証済みと判定されないものは `error` にする |
| L15 | 利用者の入力と外部データで、固定のホスト以外へ要求させず、ワークフローのコマンドに注入させない | SSRF、`verify.yaml` と `macos-verify.yaml` のランナーでの任意のコマンドの実行 | 危険側 | 書く | タグ名とアーカイブの中のパスは、ワークフローのコマンドの引数になる |
| L16 | VST 3 の絞り込みと VST の語の表示を、VST 3 のバンドルを検出したプラグインに限る | Steinberg のガイドラインの文面に反する表示になる | 危険側 | 書く | ADR 0004 で文面にすべてしたがうと決めており、違反は外部から指摘されるまで気づけない |
| L17 | 秘密情報と開発者の連絡先を、応答とページに出さない | 利用者のトークンの漏洩、連絡先の収集 | 危険側 | 書く | エラーの経路は正常系のテストで通らない |
| L18 | 名前を変えたプラグインの旧い名前を、別のリポジトリに使わせない | 旧い URL からなりすましのプラグインへ誘導される | 危険側 | 書く | 名前の一致による検索が旧い ID より優先されると、利用者は気づけない |
| L19 | 定期処理の 1 回の起動が、外部呼び出しと D1 のクエリの予算に収まる | 定期処理が上限で落ち、掲載中の配布物の照会し直しが止まる。新たに収録されたマルウェアを検出できない | 危険側 | 書く | プラグインの件数が増えて初めて超える |
| L20 | 審査の基準の正本とコードの項目の ID と、重大とする場合が一致する | 判定しない項目が生じる。重大な指摘が掲載を止めない | 危険側 | 書く | 正本の文書とコードの二重管理で、片方だけの更新が起きる |
| L21 | `submit_plugin` と確認のモードの回数の上限と、OAuth の経路の IP アドレスごとの上限 | 登録の乱用。OAuth の経路への大量の要求で、KV の書き込みの費用が膨らむ | 可用性 | 書く | 攻撃を受けるまで壊れていることが分からず、ほかに検知の手段が無い |
| L22 | 表示の補助。機械翻訳の整形、週間のランキング、画像の遅延読み込み、canonical、noindex、言語の判定 | 表示が崩れる、検索エンジンの扱いが変わる | 安全側 | 新たには書かない | 壊れても掲載の可否と権限に影響しない |
| L23 | 作者への版の状態の分類と、AI Gateway の支出の上限と Workers AI の無料枠の不足によるレビューの待ち | 作者への案内が不正確になる。不要な確認待ちが増える | 安全側 | 新たには書かない | 掲載の可否は L07 で守っている |
| L24 | GitHub のトークンの更新 | 作者が再びサインインする必要が生じる | 安全側 | 書かない | 失敗しても管理権限の確認が通らなくなるだけで、権限は広がらない |
| L25 | 定期処理からの `verify.yaml` と `macos-verify.yaml` の起動 | 新しい版の掲載が進まない | 安全側 | 新たには書かない | 起動しなければ掲載されないだけ。実環境で確かめる |

## テストシナリオ

### 権限: MCP

ツールの呼び出しは `POST /mcp` に JSON-RPC の `tools/call` で送ります。ツールの結果の失敗は、HTTP の 200 と、結果の本文の `code` で返します。

| ID | ツールと要求 | 利用者の種別 | 期待する結果 |
| --- | --- | --- | --- |
| P01 | `submit_plugin` | 未サインイン | 401。`WWW-Authenticate` に `resource_metadata="<ORIGIN>/.well-known/oauth-protected-resource/mcp"` を含む |
| P02 | `submit_plugin` | 偽のトークン | 401。`WWW-Authenticate` に `error="invalid_token"` を含む |
| P03 | `submit_plugin` の確認のモード | 未サインイン | 401 |
| P04 | `list_my_plugins` | 未サインイン | 401 |
| P05 | `Mcp-Name: search_plugins` を付け、本文で `submit_plugin` を呼ぶ | 未サインイン | 400 |
| P06 | `Mcp-Name: search_plugins` を付け、本文で `list_my_plugins` を呼ぶ | 未サインイン | 400 |
| P07 | `submit_plugin` | サインイン済み。対象リポジトリの管理者でない | 200。`code` が `not_admin`。`plugins` の行が 0 件 |
| P08 | `submit_plugin` の確認のモード | サインイン済み。対象リポジトリの管理者でない | 200。`code` が `not_admin`。Workers AI を呼ばない |
| P09 | `list_my_plugins` に他人のプラグインの `pluginId` を渡す | サインイン済み。所有者でも登録者でもない | 200。`plugins` が空。GitHub API を呼ばない |
| P10 | `list_my_plugins` | サインイン済み。登録者だが、現在は管理者でない | 200。`plugins` が空 |
| P11 | `list_my_plugins` | サインイン済み。管理者 | 200。検査中の版と `blockers` を返す。P09 と P10 の対照 |

P05 と P06 の 400 は、配信プラグイン倉庫くんの実装と同じ値です。

P07 から P10 の GitHub API のモックは、利用者のトークンで呼ばれたときだけ `permissions` を返すようにします。管理権限の確認をアプリの認証情報で行う誤りがあれば、`permissions` が無い応答を受けて P07 が失敗するためです。

### 権限: 配布物の検証の受け口

対象は `GET /internal/checks/pending`・`POST /internal/checks/results`・`GET /internal/macos-checks/pending`・`POST /internal/macos-checks/results` の 4 つです。次の表の各行を、4 つの経路のすべてで確かめます。表の `verify.yaml` は、`/internal/macos-checks/` の経路では `macos-verify.yaml` と読み替えます。

| ID | トークン | 期待するステータスコード |
| --- | --- | --- |
| P20 | `Authorization` ヘッダーが無い | 401 |
| P21 | 別のリポジトリのワークフローのトークン。`aud` は一致する | 401 |
| P22 | 別のリポジトリから、本サービスの `verify.yaml` を再利用のワークフローとして呼んだトークン。`job_workflow_ref` は一致し、`repository` が違う | 401 |
| P23 | 本サービスのリポジトリの別のワークフローのトークン | 401 |
| P24 | main 以外のブランチで動作した `verify.yaml` のトークン | 401 |
| P25 | `main` という名前のタグで動作した `verify.yaml` のトークン。`job_workflow_ref` の末尾が `@refs/tags/main` | 401 |
| P26 | 期限切れのトークン | 401 |
| P27 | `aud` が違うトークン | 401 |
| P28 | `iss` が違うトークン | 401 |
| P29 | GitHub が公開していない鍵で署名したトークン | 401 |
| P30 | 署名のあとでクレームを書き換えたトークン | 401 |
| P31 | `alg` が `none` のトークンと、公開鍵を秘密鍵とみなした `HS256` のトークン | 401 |
| P32 | 本サービスの認可サーバーが発行した MCP のアクセストークン | 401 |
| P33 | 本サービスのリポジトリの main で動作した `verify.yaml` のトークン | 200。P20 から P32 の対照 |
| P34 | 本サービスのリポジトリの main で動作した `macos-verify.yaml` のトークンで、`/internal/checks/` の経路を呼ぶ | 401 |
| P35 | 本サービスのリポジトリの main で動作した `verify.yaml` のトークンで、`/internal/macos-checks/` の経路を呼ぶ | 401 |

P21 と P27 を分けるのは、`aud` が要求側で選べる値で、照合の境界にならないためです。拒否の根拠は `repository` と `job_workflow_ref` の照合です。

P34 と P35 は、一方のワークフローの乗っ取りで、もう一方の経路の結果を書かせないためのテストです。

| --- | --- | --- | --- |
| P40 | `/plugins/<owner>/<repo>` | 検査待ちのプラグイン | 404。本文にダウンロードの案内を含まない |

### 一覧と検索に含めないもの

含まれるものによって公開の範囲が決まる経路では、含まれてはいけないものが含まれないことを確かめます。1 つのテストで、次の 3 つのプラグインを用意し、各経路の結果を確かめます。

- 検査待ちのプラグイン
- 管理停止のプラグイン
- 掲載中のプラグイン。対照として、すべての経路に現れることを確かめる

| ID | 経路 | 期待 |
| --- | --- | --- |
| V01 | `search_plugins` | 検査待ちと停止を含まない |
| V02 | `get_plugin` | 検査待ちは、未登録の ID と同じ `not_found` を返す。応答に `pending` とダウンロード URL を含まない。停止はダウンロード URL を返さない |
| V03 | Web の一覧と検索結果 | 検査待ちと停止の詳細ページへのリンクを含まない |
| V04 | 右の列の新着と週間のランキング | 検査待ちと停止を含まない |
| V05 | `/sitemap.xml` | 検査待ちと停止の詳細ページを含まない |

VST 3 の絞り込みも、同じ形で確かめます。

| ID | 状況 | 期待 |
| --- | --- | --- |
| V10 | 宣言ファイルの `formats` に `vst3` を書いたが、中身の検査で CLAP のバンドルだけを検出したプラグイン | `search_plugins` の `format: vst3` と Web の `?format=vst3` の結果に含まない |
| V11 | 同じプラグインの詳細ページ | 「VST® 3」の表示・VST Compatible ロゴ・商標の注記を含まない |
| V12 | VST 3 のバンドルを検出したプラグインの詳細ページ | 「VST® 3」の表示の隣のロゴと、商標の注記を含む。V11 の対照 |
| V13 | 規格の選択肢に「VST® 3」を出す一覧と検索結果のページ | VST® 3 のタグの条件を説明する文と組にしたロゴと、ロゴを伴う商標の注記を含む。絞り込みの隣に、説明の無いロゴを置かない |
| V14 | VST の語を書く固定ページ | 7 言語のすべてで、VST の語より前にロゴを伴う規格の行を置く。`about`・`policy`・`submit`・`security` はロゴと商標の注記を含む。対照として、`terms` は商標の注記を含まない |

### 掲載状態の算出

掲載状態と案内する配布物を求める関数を、入力の組み合わせで確かめます。リリースと検査結果を引数で渡し、D1 を介さずに確かめます。各行の期待は、[データモデル](data-model.md) の算出規則と [審査の基準](review-criteria.md) の掲載の条件によります。

| ID | 状況 | 期待 |
| --- | --- | --- |
| S01 | アーカイブの `content_checks` が `pending` または `error` | 版を掲載しない |
| S02 | 2 つのアーカイブの一方が `vst2_detected`、他方が条件をすべて満たす | 版を掲載しない。`admin_approved_at` があっても掲載しない |
| S03 | 2 つのアーカイブの一方が `no_plugin`、他方が条件をすべて満たす | 版を掲載し、`no_plugin` のアーカイブを案内しない |
| S04 | すべてのアーカイブが `no_plugin` | 版を掲載しない |
| S05 | Windows のアーカイブが条件を満たし、macOS のアーカイブの `macos_signing_checks` が `failed` | 版を掲載し、Windows のアーカイブだけを案内する |

## 書かないテスト

| 書かないテスト | 理由 |
| --- | --- |
| 権限がある人に 200 が返るだけのテスト | 何も守れない。対照として P11・P33・P43・V01 から V05 の掲載中のプラグインだけを置く |
